## 3. 穿透的结算方式

- 原生（反汇编核对）：187 的子弹动作类为 `BattleActionBullet`。其 `attackAction`（0x177754，r1 子弹、r2 目标）在目标受伤时，除子弹 +0x1c 或 +0x20 为 −2 外把子弹预约为状态 60（0x17777c，移除）；`BattleBullet::attack`（0x1dceb2）每结算一个目标把剩余目标数（+0x148）减 1，减到 0 时关闭攻击框。因此每发命中目标数只决定“接触当帧最多结算几个重叠目标”，子弹在该帧后消失。同一颗子弹的攻击 ID（+0x144）由 `BattleUnit::damage` 写入目标的受击 ID 环（+0x328 起 80 项），环中已有该 ID 时不再结算。未来 MV-280C 绝招的子弹（每发 999）实测也在命中当帧消失。
- 本单位（R1，行为 `piercing_shots`，核心 r100）：对带此标记的单位（子弹 +0x128 为发射方 UnitID）所发射的子弹，命中后不预约状态 60，子弹继续竖直下落（每 tick 10），依次结算之后接触的目标，落地消失。
- 同一颗子弹对同一目标只结算一次：除原生受击 ID 环外，子弹工作区记录已结算的目标——+0x24 子弹攻击 ID 作标签（与当前 ID 不同即视为空，对象池重用时不读旧数据）、+0x26 个数、+0x28 起最多 14 个目标实例号（+0x62）；已在其中的目标在 `attackAction` 入口直接返回 0（不结算、不减剩余目标数）。子弹停留在大体积目标的图像范围内时不会连续受伤；超过 14 个目标后只由受击 ID 环去重。状态全部保存在客体内存中（回滚快照一并保存）。

## 2. 结论摘要

1. **MSA 的 UNION 不再合体。** 合体单位（254 / 377 / 381）的普攻、远距与绝招状态（30 / 40 / 50）都播放同一个分离动作（槽 10），第 39 tick 生成 1–3 号机三个单位，第 40 tick 把自身移到画面外、不再绘制，此后只在三机全部消失时把自身移除。代码中没有三机重新组成合体单位的路径（`isDivideAfter`、`preDivide` 无调用者；`summonUnit`、`createUnit` 各只有一处调用，均在分离流程中）。
2. 第 318 节按函数名推测的“飞艇返回停靠”与实际不同：`union2BaseReturn` 是 2 号机每次近距攻击后升到画面上方、移到**本方据点**上空再下降到离地 285 处重新出击；`union2TouchDown` 是 2 号机损毁坠落时触地转入爆炸。
3. 合体形态在出场时置身体状态 Guard（不受伤），分离后另置 NoTarget、DontTouch，因此合体形态在 MSA 中实际上不承受伤害；作战与被击毁的是三个子单位。
4. 生命有两种来源：一般情形（如玩家出击的 377）三机各按自身数据行（378–380 Lv40 各 90750）；合体单位对象序号为 1（推定为关卡开局放置的首领，未运行核实）时，3 号机取合体单位最大生命的 30%、2 号机 20%、1 号机取余下部分，合体单位生命归零。
5. 2 号机（非 BOSS 版 255 / 379）出场即置 NoTarget 与 DontTouch：不会被地面单位选为目标，只有攻击框恰好与其受击框相交时受伤。BOSS 版 383 不置这两项。
6. 战斗槽没有 op19 75% 缩小（只有编队 / 菜单槽 0–2 与部件 121–132 写 op19 70%），既有“75% 改 100%、偏移与判定框 × 4/3”的规则不适用于 UNION；战斗中照原尺寸移植，编队页 / 菜单的 70% 副本对应 MSD 的缩小部件副本。
7. 音效全部为 MSA 通用音效（`m_sound_data`）：211 `B4_STGUN`、212 `B4_TCAN4`、213 `B4_VUL1`、226 `B4_PDMG`、261 `BS33TUKA`、327 `BH_CHARGE`、332 `B4_MOVE2`、375 `mirai_energy`、491 `cata2`、492 `charge3`。这些 SoundID 在 MSD 原生音效表的范围内（0–1030 中非空闲区段），是否与 MSA 同名同音待实施时逐条核对。
8. 图集已含三机、分离动作、导弹、能量弹、炸弹与爆炸所需的帧；MSA 中 1 号机不发射绿色核心弹（其绝招为水平导弹 3 发与弹道导弹 1 发），按 MSA 移植时不需要用户素材表补帧。

## 4. BattleAction_UnionCombine（合体单位；`UnionCombinePlayer` 只把续战位置改为 (0, 0)）

### 4.1 update（0xdac7e8）

- 阶段 0：`initialize` 置 Guard；若为续战单位（虚表 +0x180）且当前生命 < 最大生命，直接按“已分离”处理（`postDivide`），否则阶段 1。
- 阶段 3（已分离）：动作演示中转 `actionViewUpdate`；否则按 +0x28 / +0x2c / +0x30 查找三机，三者都不存在时移除自身，其余情况不做任何事。
- 状态（跳转表 0x4670e41）：10 待机播槽 6；20 移动播槽 7、预约 10，377 另在移动中检测前方敌人与敌方据点（0xdaca7c–0xdacbec，满足时转 30），按移速前进；30 / 40 / 50 第 0 tick 置 DontShortAttack、0x200、DontSpAttack、阶段 2 并播槽 10，第 39 tick `summonUnit`，第 40 tick `postDivide`；70 播槽 12（结束预约 10，移速 0）；80 播槽 11；100 / 110 / 120 播槽 13，结束时在 (0, −50)、(100, −30)、(200, −50) 放 0xff17、0xff04、0xff17 后移除。

### 4.2 summonUnit / createUnit（0xdad004 / 0xdadb2c）

- `summonUnit`：当前生命 ≥ 最大生命时 `createUnit`；否则（续战）按 UnitID 找已存在的三机并记序号。之后置 Guard、NoTarget、DontTouch，非演示时置 DontShortAttack、0x200、DontSpAttack，+0xacc = 3。
- `createUnit`：按合体单位的 UnitID 取三机（254→255–257、377→378–380、381→382–384），以 0x10ed350 在本单位位置加朝向偏移生成：3 号机 (0, 0)，2 号机 (+70, −276)，1 号机 (+390, −6)；设各机身体尺寸（3 号机 59×97、2 号机 70×84、1 号机 66×111，用于 `setObjectSize`）；1、3 号机互记序号（`union1PositionAdjust` / `union3PositionAdjust` 用）；各机 +0xacc = 1、续战位置 = 合体单位的续战位置。

### 4.3 生命（0x10f979c）

合体单位对象序号为 1 且非演示时调用：3 号机最大与当前生命 = 本队第一个对象（即合体单位）最大生命 × 30%，2 号机 × 20%，并从合体单位当前生命中扣除；1 号机取合体单位余下的当前生命，合体单位生命置 0。其余情形三机生命取各自数据行。

### 4.4 postDivide（0xdad228）

x 移到画面外（我方：−精灵宽；敌方：战场宽 + 精灵宽），动作 −1（不绘制），阶段 3，置 NockbackGuard。

### 4.5 弹体、效果与攻击结算

- 槽 10（分离）：op22 142 生成随合体单位存在的弹体（`BulletAction_UnionCombine`：合体单位不存在、回到阶段 1 或动作为 −1 时移除；脚本 142 为攻击框 8、先加速后 2.5 / tick 前进），op12 143–149 为同样跟随合体单位的部件与烟雾（`EffectAction_UnionCombine`，另在自身动画结束时移除）。预览中可见 1 号机前冲、飞艇上升与分离。
- `attackAction`（0xdad594）：攻击结算组不为 30 / 40 / 50 时改用状态参数 13、14、18 作为伤害、第二参数与属性。

### 4.6 动作演示（`actionViewUpdate` 等）

演示中合体单位的 30 / 40 / 50 令三机分别进入同一攻击状态（30：三机近距；40：2、3 号机远距；50：三机绝招），全部结束后回到 10；重新开始演示时移除三机并复原合体形态。

## 10. MSD 侧实施方案（拟定，待第 11 节决定后细化）

- 单位（稳定键只追加）：`s1xlv.union`（1093，合体形态，可购买 / 作首领）、`s1xlv.union_01` / `_02` / `_03`（1094–1096，内部单位）。三机的 UnitID 写入合体单位的子单位字链（开战预载音效）。
- 动作类：沿用侵略者类基准 192 与自定义状态机钩子（同钢铁死亡蠕虫、Fall Climber），新行为 `union`（一个标记、按角色字区分合体 / 1 / 2 / 3 号机），参数存 ZSpec 字；核心 r118 起。逐条按第 4–7 节实现：Guard 合体形态、第 39 tick 同时生成三机（生成方式在实施时核查：钩子内嵌套调用能否建立对象；不能时改为与 Fall Climber 相同的尾调用、分 3 tick 生成并在文档中记明偏差）、画面外等待、三机互相推挤、2 号机返回据点与再下降、3 号机投弹、三机损毁冲撞与爆炸序列、合体单位随三机消失而移除。
- 动作记录：MSA 3 张图集转为 MSD 图集；150 个脚本按 MSD 指令语义转换（op22 第 2 值改 0、MSA 24 / 26 / 28 按回调语义处理、补 op3 使损毁动作不缺受击框）；部件判定（受击框按部件条带，核心 r95 机制）。
- 界面：编队页 / 菜单槽以 70% 部件副本（同 MSA 槽 0–2）；单位菜单动作演示按 4.6 节由合体单位带三机演示；`draw_priority` −80、`minimap_marker`、`special_effect_size` 按 MSA 光圈。
- 回滚：状态全部放在客体内存；随机数只用于效果位置时取帧计数与对象序号，不用对象地址。
- Energy Pod 的接入位置（本任务不做）：2 号机近距攻击槽 71 的舱门对象（op12 110，第 0 tick）与 2 号机下降结束（状态 22 → 10）两处可作放出时机。
- 工作量：四个动作类约 12.5 KB 的 MSA 代码，预计核心钩子与 Fall Climber（r115–r117）同量级或更多，需多次修订；未定事项影响生命、目标选择与是否追加合体流程。

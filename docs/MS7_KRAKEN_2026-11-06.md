## 4. 引擎可行性（核心 r147，只读反汇编与隔离探针）

### 4.1 胜利条件：首领本体作敌方据点单位（已探针验证）

- 原生：敌方据点由 `BattleScene::setupResourceAll` 调用 `BattleObjectManager::createKyotenUnit(队伍, UnitID, …)` 建立；UnitID、最大生命、等级取自任务记录（`BattleControllerEnemy::getKyotenUnitID` / `getKyotenMaxHP` / `getKyotenUnitLevel` 读 [控制器 +0x3ac] 的词 3 / 4 / 5）。`BattleController::update` 每帧检查据点 `getHpRate`（+0x308 / +0x304），≤ 0 时 `notifyEventBaseUnitDead` → `BattleScene::battleFinish`（`engine/dis_ctrl_update.txt`、`dis_scene_basedead.txt`、`dis_ctrl_enemy.txt`）。原版据点类 `BattleAction_Kyoten` 在死亡状态第一帧放 0xff11 爆炸并移除；原生另有会攻击的据点类（`BattleAction_KyotenNeko`、`IronNokanya`）。
- 现状：自制关卡的任务记录以模板 1011 为底，词 3 / 5 保持模板值（0 / 0，即原版据点外观），宿主只写词 4（`enemy_base_hp`）。
- 探针 `probe_base_unit.py`（隔离存档，`runs/kb228_*`、`runs/kb1101_*`，截图 `overview/probe_kb228.jpg`）：在内存中把第 6 关任务记录词 3 改为 228（原生 REBEL WALKER）或 1101（带炮管的雷贝尔沃克），词 5 改为 40。结果：据点建立为该单位（UnitID 228 / 1101，生命 = 词 4 的 80000），像普通单位一样前进、跳跃、攻击、被击退（x 1451 → 1196 → 1416），画面右上的敌方据点生命条显示其生命；把其生命写 0 后当帧对战结束，第 5 帧出现 MISSION COMPLETE，随后正常结算（S 评级与奖励）。
- 结论：首领本体可作敌方据点单位，击破即按原生流程过关；需要的改动为宿主的关卡字段（例 `enemy_base_unit`、`enemy_base_level` 写词 3 / 5，涉及 `campaign_catalog.py`、`community_campaign.py` / `event_content.py` 的任务记录编写与校验），以及首领自身的行为。
- 须注意：
  - 生命归零的当帧即进入结束流程，原生不等死亡动画。沉没演出须在生命归零之前播放（致死伤害时把生命保持为 1、不可被选为目标，演完再归零），或由核心推迟据点死亡通知。原作的完成字样在残骸下沉途中出现，归零时点可放在落入熔岩之后。
  - 敌方据点生命条显示本体生命；第一阶段本体不受伤时生命条保持满格，是否改为显示触手合计待定。
  - 关卡 `triggers` 的 `base_hp` 条件随之以首领生命百分比触发，可用于按首领生命追加杂兵。
  - 第一阶段本体不可被攻击时，我方单位推进到据点位置后的行为（NoTarget 的据点是否仍作推进终点）未测。

### 4.2 背景随战斗变化

- 现有场景图层（`src/community_content.cpp` 的 `stage_back_draw` 等）只有逐层的循环帧（计数器取余）、视差、换帧间隔与混合方式，没有按战斗状态切换图层的机制。
- 原作的背景变化为远景本体与其触手底座（7 态），以及第二阶段本体离开远景；熔岩、红月、残骸不变。建议由首领本体自身绘制远景形态：第一阶段本体（据点单位）以最低绘制优先级画“远景本体 + 底座第 k 态”，k 由已毁触手数决定，升空后改画第二阶段形态。画法与模拟状态一致，不另占回滚状态，不改场景与核心的场景代码。场景背景层画在全部对象之前，远景本体因此画在熔岩波纹与漂浮残骸层之前；静帧中两者在画面上的重叠只在底座下缘（`anim/R1_stage_mock.png`）。
- 另一做法为新增“按首领状态显示的场景图层”（场景字段 + 核心绘制钩子，状态由首领单位读出），只在需要视差或场景层级时采用。

### 4.3 首领结构（建议，待用户定）

- 本体：敌方据点单位（第 4.1 节），`internal_only`，新增行为（暂名 `kraken`）管理阶段、远景态、升空、第二阶段的悬停 / 俯冲 / 潜入与攻击、沉没。第二阶段悬停时本体在画面上沿附近，地面单位的普通攻击够不到；可只在俯冲、冲出熔岩时可被攻击（原作的反击窗口），或把受击框向下延伸，待定。
- 触手：6 个内部单位（开战时由关卡 `placed` 放置或由本体召唤），各有生命，在熔岩中时不可被选为目标、无受击框，露出时可被攻击；本体按对象序号记录 6 条触手（同 UNION 三机的做法，第 319 节），全部被毁后转入第二阶段。触手的弯曲姿态以描述符帧组合节段矩形（外环、芯筒、头部件、钻头按 16–32 个方向预先旋转，第 336 节导弹 16 方向的做法），不需要整幅烘焙大图；判定可用部件条目（核心 r95）逐节设框。
- 绘制优先级：远景本体最低（−100），前景触手与第二阶段本体在单位之后（例 −90，同 UNION / 钢铁死亡蠕虫），召唤与弹体按数据行优先级（记忆 draw-priority-f0-encoding）。

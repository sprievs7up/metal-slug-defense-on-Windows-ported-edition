# Rollback 联机 N4：网络层（2026-10-10，核心 r44）

依据：`docs/netcode/ROLLBACK_NETCODE_TASK_2026-10-09.md` 第 5 节 N4 行与第 7 节 R2–R4；`docs/netcode/N1_N2_ROLLBACK_2026-10-10.md`（N1–N3）。
本阶段实现局域网与远程的点对点连接、可靠消息、断线判定与恢复、对局协议（内容比对、比赛种子、编队锁定、再战），

（`docs/netcode/N4_TWO_MACHINE_ACCEPTANCE.md`，工具 `tools/netplay_check/`）。原生核心不变（r44）。游戏内联机菜单属于 N6，本阶段无游戏内入口。

## 2. 传输：一个 UDP 套接字承载一名对手的全部通信

远程打洞只对 UDP 可靠，因此握手、编队、结果等也在同一个 UDP 套接字上以可靠消息传送（N3 的 TCP 握手只能用于回环与局域网）。

包头 18 字节：魔数 `MSDN`、协议版本（N4 为 2，N5 起为 3）、类型、64 位连接令牌、包序号。令牌在 CONNECT 时由加入方随机生成，之后每个包都必须携带；
令牌正确而来源地址改变时（路由器重新映射端口、换网络）改用新地址（地址迁移）。

| 类型 | 用途 |
| --- | --- |
| CONNECT / ACCEPT / REJECT | 连接建立。CONNECT 每 0.1 秒重发直至收到 ACCEPT；REJECT 原因：`busy`（房间已有对手）、`protocol`（协议版本不同） |
| DATA / ACK | 可靠消息：JSON（超过 512 字节时 zlib 压缩）按 1000 字节分片，逐片序号，在途上限 32 片，累计确认加 32 位选择确认，超时重传（RTO = 平滑往返 × 1.5 + 50 ms，限制 0.1–2 秒，按次数退避），按序交付；单条消息解压后上限 4 MiB |
| INPUT | 对战输入：轮次、确认帧、本方当前帧、帧优势、首帧、个数与逐帧输入字节（每包冗余携带对方尚未确认的全部本方输入，与 N3 相同） |
| CHECKSUM | 周期校验值（每 30 帧，轮次 + 帧 + h + d） |
| TAGS（N5，协议 3） | 周期校验值的 tag（与发送方一侧绑定，每包冗余携带最近 4 个已确认校验帧；见 `docs/netcode/N5_DESYNC_AND_TAMPER_2026-10-10.md`）。CHECKSUM 保留供 N3 传输与测试 |
| PING / PONG | 每 0.5 秒心跳与往返时间（平滑系数 1/8）。往返时间包含对方每帧处理一次网络的间隔（0–33 ms） |
| BYE | 离开或判定断线时直接发送三次 |
| PUNCH | 打洞（携带会合服务器分配的打洞令牌） |

- 轮次号：再战时对战包带新轮次，上一轮迟到的输入与校验值一律丢弃。
- 断线：1 秒收不到任何包为“连接不稳定”（`interrupted`，对战由回滚会话停在最多回滚帧数处等待），超过 10 秒（`--disconnect-after` 可调）为“已断线”
  （向对方发 BYE，不再恢复）；10 秒内恢复收包即回到 `connected`，冗余输入自动补齐，对战继续。对方离开（BYE）立即结束。
- 带宽：对战中每方约 34 包/秒、1.3–1.7 KB/秒（测试实测）。
- Windows：关闭 UDP 的 `WSAECONNRESET` 报告（发往无人端口引起的 ICMP 不再中断收包）。

## 3. 连接方式

| 方式 | 流程 | 需要 |
| --- | --- | --- |
| 局域网（发现） | 房主在对战端口（默认 UDP 47631）等待，另在发现端口（UDP 47630，`SO_REUSEADDR`）应答查询；加入方向 255.255.255.255 与各网卡 /24 定向广播地址发送 QUERY（每 0.25 秒），列出房间（名称、版本、内容摘要前 16 位、对战端口、空闲/已满），选择后直连 | 不需要服务器；防火墙允许 |
| 局域网 / 远程直接连接 | 加入方填写 `IP:端口` 直连。远程时房主路由器需转发 UDP 47631，或由 `upnp_igd` 自动请求（路由器支持 UPnP 时），并显示路由器公网 IP | 远程需端口转发或 UPnP |
| 远程会合 + 打洞 | 房主用对战套接字向会合服务器登记，得到 6 位房间码（每 15 秒保活）；加入方用房间码取得房主的公网与内网地址，服务器同时把加入方地址与打洞令牌发给房主。房主向加入方各候选地址发 PUNCH，加入方向房主各候选地址发 CONNECT；收到对方 PUNCH 时把其来源地址加入候选（对称型 NAT 一侧的新端口）。加入方在打洞期间每秒重复 join，房主漏收的通知由此补发 | 社区自建的会合服务器（只交换地址，不转发对战数据） |

无法连接时的说明（中英文，`connect_failure_text`）：对方无回应、打洞失败（附可尝试的网络设置，说明不提供中继）、房间已满、协议版本不同、房间码不存在、服务器无回应、请求过于频繁、服务器房间已满。

打洞结果与路由器类型的关系（以 `SimNat` 在回环上验证，第 6.1 节）：双方同为完全锥形、双方同为端口受限锥形、对称型与完全锥形（房主或加入方任一侧为对称型）之间可以打通；
对称型与端口受限锥形之间、双方都是对称型时打不通，按 R3 报告无法连接。

## 4. 对局协议（`netplay_match.Match`，可靠消息之上，非阻塞）

1. **hello**：双方交换协议版本、内容清单摘要（M7）、地图池、输入延迟偏好、随机数 nonce。摘要相同即兼容；不同时双方交换完整清单，
   各自以 `content_manifest.diff` 列出差异并拒绝（双方各从本方角度列出，例如一方“缺少模组”，另一方“对方没有此模组”）。地图池不同也拒绝。
2. **编队（R4：只在开战前一刻得知对方编队）**：锁定编队时只发送承诺值 BLAKE2b（规范化编队 + 轮次 + 16 字节随机盐）；双方都已承诺后才揭示编队与盐，
   收到后核对承诺值与编队结构（10 格，每格为空或 [单位, 等级 1–40]；单位为 1–399 的原版编号或已载入的可选社区单位稳定键）。
   修改过的客户端既不能在锁定前得知对方编队，也不能在得知后更换本方编队；承诺不符时拒绝（`deck_commitment`）。
3. **本轮设定**：比赛种子与地图由双方 nonce 共同决定（任何一方都不能单独选择）：种子 = BLAKE2b(房主 nonce + 加入方 nonce + 轮次) 的 31 位，
   地图 = 地图池[另一摘要 mod 池大小]。输入延迟取双方值（指定或自动）中较大者。房主为 P1（左），加入方为 P2（右），画面不镜像（R4）。
   N4 验收工具的地图池暂为 1011、1055、2121、3165；正式对战地图池（官方 Wi-Fi 对战）在 N6 核查后作为数据文件计入内容清单。
4. **第 0 帧同步**：双方开战并到达联机第 0 帧后交换校验值与原生战斗帧号（此后到收到对方 go 之前**不推进原生帧**），一致后互发 go，收到对方 go 即开始；
   双方因此在约同一时刻开始。不一致时拒绝（`frame0_mismatch`）。
5. **结果**：对战结束后交换已确认帧的全部周期校验值，比较共同帧。
6. **再战（R4）**：任一方请求后对方也请求即进入下一轮：新的 nonce → 新种子与地图，重新锁定编队。离开时先发离开消息，待本方已发出的可靠消息
   （如结果）全部被对方确认（最多 3 秒）后再断开，对方因此一定先收到结果再收到离开。

自动输入延迟（偏好为 0 时）：单向延迟（往返的一半）折算帧数后减 4，限制在 2–6 帧，使常见网络下回滚深度不超过约 4 帧。
时间同步（帧提前量调节）沿用 N3：双方报告帧优势，领先超过 1 帧的一方每 3 个显示帧让出 1 帧；单向延迟不对称时无法区分（往返测量的固有限制），
测试中（单向 20 ms 对 150 ms）双方回滚次数相近、无等待。

## 5. 与回滚会话的衔接（`tools/netplay_check/netplay_check.py` 的 `battle()` 为参考实现）

1. 双方锁定后，以本轮设定建立 `NetplayBattle`（本方一侧、种子、延迟），`prepare` 开战，逐帧推进直至 `ready()`，`begin()` 得到第 0 帧校验值并发送 ready。
2. 等待对方期间只处理网络、不推进原生帧（第 0 帧状态必须相同）。
3. 对战中每显示帧：`session.tick()`（内部经 `PeerLink.poll()` 收发输入与校验值，必要时回滚）后 `match.poll()`（可靠消息、连接状态）。
4. 结束条件：分歧、已确认的战斗结束帧之后 30 帧、帧数上限（测试）、断线、对方离开。断线或对方离开时 `session.end()` 后 `lab.finish()`，
   原生闸门合拢后回到准备界面（体面结束）。

### 5.3 进程历史与第 0 帧校验（本阶段发现并处理）

两台电脑开战前的经历不同（例如一方先打过本地 LAB 对战）。首次测试中，先进行 600 帧本地对战的一方第 0 帧深度校验值不同，匹配被拒绝。
逐区比较全新进程与有历史进程在第 0 帧的客体内存（静态数据区与顶部共享区）：非指针差异 697 字，分布于静态单例 `BattleObjectManager`
（0x10977f50，暂存字段保留上一场的数值，全新进程为 0）、`BattleSpriteFactory`（0x10966fa0，图像缓存与计数）、少量界面与动画计数、客体栈残留与 LAB 音效统计。
以单机参照对比（同一种子、编队与输入）：四种历史（600 帧 1165、2400 帧 1165 两种编队、3000 帧 1011、1200 帧 3165）下，第 30 帧起全部周期校验值与全新进程相同、
结束帧相同；唯一差异是第 0 帧对象管理器的暂存字段（在第 30 帧前被本场覆盖）。因此第 0 帧校验值不计对象管理器（周期校验仍包含），
修改后上述历史与全新进程第 0 帧也一致，“一方有历史”的联机对战通过（t6）。该结论来自所测历史；N5 的周期校验分歧处理仍需保留。

## 8. 已知限制与后续

- 两机验收待用户进行（真实网卡上的局域网广播、不同网络之间的打洞、路由器 UPnP、跨 CPU 一致性、低配电脑的帧耗时）。
- 只支持 IPv4；不提供中继（R3）。连接不加密：令牌防止路径外的伪造与注入，不防路径上的窃听或篡改；清单与输入的真实性属于 N5 反作弊范围。
- 局域网发现需要防火墙允许入站 UDP 47630/47631；网络为“公用”时可能收不到，可改用按 IP 直连。
- 进程不重启时可从中断恢复（10 秒内）；进程崩溃后不能重新加入原对局（体面结束）。
- 往返时间包含对方每帧处理网络的间隔；时间同步无法区分不对称的单向延迟。
- 游戏内入口（联机菜单、房间、房间码与服务器地址的输入与保存、网络状态显示、投降/离开叠层、设置项）属于 N6；回放与观战属于 N5.5。

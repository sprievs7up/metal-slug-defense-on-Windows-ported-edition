# Rollback 联机 N6b：远程联机（地址 + 房间码直连，IPv4 / IPv6）（2026-10-10，核心 r45）

依据：`docs/netcode/ROLLBACK_NETCODE_TASK_2026-10-09.md` 第 7 节 R9（N6a 完成后用户明确）；N6a 文档 `docs/netcode/N6A_REGULAR_NETPLAY_2026-10-10.md`；
N4 网络层文档。原生核心不变（r45）。观战入口按用户意见作为后续内容，本阶段不实施；N4 的会合服务器代码保留，不出现在游戏界面中。

## 1. 用户决定（R9）

- 现阶段不搭设专用服务器：社区反馈显示知道本项目的玩家多数来自南美而非东亚，服务器的部署思路会完全不同，留待以后。
- 远程联机为“地址 + 房间码”直连：房主建房后得到本机可被访问的地址:端口与 6 位房间码，对方在游戏中输入两者即可连接（例：`172.0.0.1:11111` 与 `XXXXXX`）。
- 同时支持 IPv4 与 IPv6（用户先选“暂不加入 IPv6”，随即更正为加入）。
- 房主的公网 IPv4 只经路由器 UPnP 取得；UPnP 不可用时以文字说明，不访问 STUN 等外部服务。
- 远程对战的输入延迟默认自动（按网络延迟 2–6 帧，双方取较大值）；局域网仍为 2 帧。
- 另：用户报告换头像时原版 Wi-Fi 界面（VERSUS REQUEST、RANKING、ACHIEVEMENT 等）重新出现，本阶段一并修复（第 4 节）。

## 2. 前提：房主必须能被对方直接访问

不经任何服务器时，对方的包必须能直接到达房主电脑上的对战端口。可行的情形：

1. 房主路由器支持 UPnP：建房时游戏在后台请求路由器转发端口，并取得路由器的外网地址显示出来。
2. 房主在路由器上手动转发 UDP 端口（窗口中可更改端口，与路由器设置一致）。
3. IPv6：没有 NAT。但不少路由器默认阻挡外来的 IPv6 连接，是否可行需实测。
4. 双方使用虚拟局域网软件（Radmin VPN、Hamachi、ZeroTier 等）：输入对方在虚拟网中的地址。

房主处在运营商级 NAT 之后（没有自己的公网 IPv4）时，1、2 都无效；游戏在 UPnP 取得的外网地址属于 100.64.0.0/10 时提示这一情况，
建议改用 IPv6、虚拟局域网，或由对方建房。外网地址为内部地址时（前面还有一台路由器）提示在上一层路由器转发。

## 3. 玩家可见流程

- 主菜单“對戰” → VERSUS 页“远程”卡片（不再灰显）→ 与局域网相同的 Wi-Fi VERSUS 大厅。
- **建立房間**：窗口显示房间码与“把下面其中一个地址与房间码告诉对手”的地址列表——
  公网 IPv4（UPnP 成功时，标注“路由器已开放端口”）、IPv6（全局地址）、局域网 / 虚拟局域网（IPv4 与 IPv6 ULA）；
  UPnP 进行中、失败、运营商级 NAT、内部地址、本机没有 IPv6 时显示相应说明；底部显示端口与“更改端口”（1024–65535，保存）。
- **加入房間**：窗口有“房主地址”“房间码”两栏。地址可写 `203.0.113.5:47631`、`[2001:db8::5]:47631`、无括号的 IPv6（端口取默认）或域名（如动态域名）；
  省略端口时为 47631。Tab、Enter 或点击切换栏位，房间码自动转为大写。上次输入的地址会保留。
- 连接失败时显示“無法連接”与原因：对方没有回应（并说明房主需能被访问、防火墙）、房间码不正确、无法解析地址、房间已满、版本不同、内容不同（列出差异）。
- 连上之后与 N6a 相同（房间、準備、对手画面、对战、再战、回放）；房间窗口显示输入延迟“自动（按网络延迟 2–6 帧）”。
- 局域网模式不变，另有两点：从局域网列表加入时自动带上房间码；“输入地址”同样需要房间码。

## 4. 实现

| 文件 | 内容 |
| --- | --- |
| `netplay_net.py` | 协议 5。双栈端点：IPv4 套接字之外，在同一端口另开 IPv6 套接字（`IPV6_V6ONLY`），按目的地址的地址族选择套接字；地址统一为 (主机, 端口)。`ipv6=None` 时 IPv4 绑定 0.0.0.0 才开 IPv6（绑定 `::`），字符串为指定地址（测试用 `::1`），False 不开；IPv6 不可用或端口被占用时只用 IPv4。`split_address`、`resolve_addresses`（IP 字面量不查询域名服务，域名同时取 IPv4 与 IPv6）、`format_address`、`ipv6_kind`（全局单播 / ULA，排除 Teredo、6to4、文档地址）、`local_ipv6`。`Listener(code=)`：连接请求中的房间码不符时以 `wrong_code` 拒绝（不区分大小写，房间仍可被正确的房间码加入；观战连接不在此检查）。 |
| `content_manifest.py` | 协议 5 |
| `netplay_lobby.py` | 远程模式（`open('remote')`）：输入延迟默认 0（自动）；房主在后台线程请求 UPnP 并按外网地址分类（ok / cgnat / private / failed），房间关闭时删除映射；房主窗口的地址列表与说明、端口更改；加入窗口的两栏输入、域名在后台线程解析；失败原因的四语言文字；隐藏表在原生弹窗场景（119–122）中保持 |
| `netplay_profile.py` | `port`（房主端口，0 为默认）与 `last_address`（上次输入的地址），与名称同存于存档目录的 `netplay_profile.json` |
| `lab_versus_page.py` | “远程”卡片启用，进入同一大厅；移除“準備中”灰显 |
| `lab_runtime.py` | 大厅窗口中 Tab 键转为切换栏位 |

以上已有镜像的模块均有 `src/` 镜像并逐字节一致；`lab_versus_page.py` 不设镜像。

### 4.1 换头像时原版界面重新出现（用户报告）

原因：drawConv 隐藏表只在 Wi-Fi 菜单场景（66、67）写入；换头像、留言选择、首次说明等原生弹窗属于场景 119–122，进入弹窗时隐藏表被清除，
Google Play 图标、VERSUS REQUEST、RANKING、ACHIEVEMENT 等随之出现。改为大厅处于菜单状态且场景为菜单或弹窗时都保持隐藏表。
VERSUS REQUEST 由按 y 坐标通配的一项隐藏，弹窗中同样需要；截图核对头像弹窗的 12 格与留言选择弹窗的选项完整，没有被误隐藏。

### 4.2 测试用环境变量

`MSD_NETPLAY_BIND6`（IPv6 绑定地址，测试用 `::1`）、`MSD_UPNP_TARGET` / `MSD_UPNP_BIND`（模拟路由器的 SSDP 地址）、`MSD_NETPLAY_NO_UPNP=1`（不请求 UPnP）；
N6a 已有 `MSD_NETPLAY_BIND`、`MSD_NETPLAY_PORT`、`MSD_NETPLAY_DELAY` 等。玩家使用时不需要设定。

## 5. 验证

## 6. 限制与待办

- 房主不可被访问时（运营商级 NAT、路由器阻挡外来 IPv6、无法转发端口）连不上；不提供服务器与中继（R9）。
- 公网 IPv4 只能经 UPnP 得知；UPnP 不可用时由玩家自行查询（窗口中有说明）。房主公网地址变化（动态 IP）时需重新告知；可用动态域名。
- 链路本地 IPv6（fe80::）不支持；IPv6 隐私地址会定期更换，房主窗口显示的是当时有效的地址。
- 局域网发现只用 IPv4 广播（同一局域网中的 IPv6 房间可按地址加入）。
- 大厅文字只有繁中、简中、日文、英文；西班牙语、葡萄牙语等界面显示英文。
- 观战入口、会合服务器的界面接入留待以后。

## 1. 已定规则

### 1.1 本次决定（R7，2026-10-10）

1. 常规联机对战与原版 Wi-Fi 对战相同：使用玩家当前使用的编队；全部等级按玩家当前的发展进度决定，包括单位等级、据点等级与我方阵营强化等升级项目。
   该模式与 LAB / 本地双人对战的自选设定模式相区别。
2. 另设可高度自定义的联机对战（LAB 式设定）。与 LAB / 本地双人对战的区别在于出兵格采用常规设计（本方 10 格的常规底栏）。局域网与远程均提供。
3. 输入延迟默认 2 帧。
4. 对局结束后（含断线、分歧、对方离开）回到房间。
5. 玩家名称参照原版 Wi-Fi 对战窗口的设计，在进入备战状态前由玩家自行输入。
6. 观战入口在准备界面；进入观战后输入房间码。局域网房间同样有房间码：房主开放房间时生成，并在局域网发现应答中携带；
   观战者输入房间码后先在局域网查找，找不到再经会合服务器查找。观战入口统一为“输入房间码”。
7. 历史记录与回放采用原版 Wi-Fi 对战的界面形式。
8. N6 拆为四段（第 2 节），每段在新对话中依次实施，完成并验证后同步两个固定运行目录。

### 1.2 补充决定（R7 补充，2026-10-10）

1. 常规联机使用的编队即原版 Wi-Fi 对战所用的编队：玩家当前默认的编队，也就是最近切换并准备在 World / EVENT 中使用的那一组。
2. 暂不计排名点数（RP）。RP 涉及日后另设专门服务器记录数据，届时再定。
3. 玩家名称保存在当前的存档文件中。
4. 画面不镜像时，P2 的左右操作栏位与 P1 相同；原生界面即如此，按原生方式处理。

### 1.3 此前已定（R3、R4、R6）

- P2 画面不镜像；联机期间不可暂停；支持再战；对方编队只在开战前一刻公开（编队承诺—揭示）。
- 地图从对战地图池随机抽取：官方 Wi-Fi 对战地图池在 N6 核查后作为数据文件计入内容清单（N4 验收工具暂用 1011、1055、2121、3165）。
- 远程：会合服务器地址 + 房间码，另备 IP:端口直连。会合服务器由社区自建，游戏不内置；打洞失败时直接提示无法连接，不提供中继。
- 局域网界面显示房间所在的地址，并提供按 IP 直连的入口。
- 联机界面单独设置历史记录与回放按钮。
- 观战每个房间最多 4 名、延迟约 2 秒；回放每场自动保存、保留最近 100 份，`kept\` 中的文件不清理（标记界面在 N6c）。

## 2. 分段

| 段 | 内容 |
| --- | --- |
| N6a 常规联机（局域网与 IP 直连） | 仿原版 Wi-Fi 对战的界面：名称输入、建立 / 加入房间、房间与准备界面；对战页“局域网”卡片作为入口。<br>局域网发现与按 IP 直连，局域网界面显示房间地址；房主开放房间时生成房间码（供 N6b 观战使用）。<br>常规对战：玩家存档的当前编队与发展等级（单位、据点、我方阵营强化），编队承诺扩展到等级与强化，第 0 帧比较双方单位实际数值。<br>窗口内运行：经会话驱动接口，常规出兵格（本方 10 格），P2 不镜像，不可暂停，输入延迟 2 帧。<br>核查官方 Wi-Fi 对战地图池并作为数据文件计入内容清单。<br>结束后回到房间、再战；断线、分歧与对方离开的提示；分歧报告保存；回放沿用 N5.5 自动保存。 |
| N6b 远程与观战 | 会合服务器地址设置（用户目录）+ 房间码；对战页“远程”卡片。<br>准备界面的观战入口与房间码输入：先在局域网查找，再经会合服务器查找；观战在窗口内运行。 |
| N6c 历史记录与回放 | 原版 Wi-Fi 对战界面形式的历史记录；列出用户目录中的回放（`netplay_replay.summary`）；标记保留（移入 `kept\`）；被拒绝的回放显示内容差异原因；窗口内播放（复用 `ReplayViewer` 的暂停、倍速、跳转）。 |
| N6d 自定义联机对战 | LAB 式设定（编队与等级、据点等级、强化、支援、地图等），双方在准备界面确认同一设定；常规出兵格；局域网与远程均可。 |

## 4. 开工时需核查的事项（N6a 起，结论记录于对应阶段文档）

- 编队（第 1.2 节已定）：读取玩家当前默认的编队。核查原生记录“当前编队”的存档字段与 World / EVENT 出击时的读取入口，联机沿用同一入口；
  存档中的旧 Wi-Fi 编队数据（AGENTS 第 105 节）不作为联机编队来源。
- 原版 Wi-Fi 对战的原生场景（1.46 `SceneFunc` 跳表，`ChangeExeST` 编号）：Profile 58–61、WiFiMenu 66–71（72 为合作 TagTeam）、WiFiDeck 73–76、WiFiResult 77–80，
  另有 2 对 2 的 WiFiDeck2on2 / WiFiResult2on2（146–153）。需核查名称输入窗口与各窗口可复用的程度；
  玩家名称保存在当前存档文件中（第 1.2 节），原版存档已有名称字段时沿用该字段，并核查其位置。
  场景表来源：`research/metal_slug_defense/content_work/event_native_audit_20261008/scenes.txt`（列出的是跳表下标，`ChangeExeST` 编号为下标加 1）。
- RP（排名点数，AGENTS 第 6.1、36.2 节）与每日加成：暂不计分（第 1.2 节）；联机结算不调用 `AddWiFiScoreSaveData` 等 Wi-Fi 计分写入，核查原生结算路径以免误写。
- 发展进度的传送：据点等级、我方阵营强化、单位等级作为编队承诺的一部分，揭示后双方以同一设定开战；对方单位的实际数值由本机按相同内容计算，
  并由第 0 帧单位摘要比较。
- 常规出兵格与 P2：画面不镜像时 P2 的左右操作栏位与 P1 相同（第 1.2 节，原生界面即如此）。核查原生 Wi-Fi 对战中 P2 操作与绘制所用的控制器路径（`BattleControllerNetPlayer` 等），
  联机沿用原生方式；LAB 分栏底栏在联机中不启用（`src/lab_hooks.cpp` 分栏绘制、`lab_versus_input.py`）。
- 窗口内性能：本机每帧回滚 8 帧时单帧最长约 33.5 ms，已接近 30 FPS 的单帧预算；N6a 在可见窗口中测量帧耗时，低配电脑待用户实测。
- 首次联机时 Windows 防火墙询问的说明文字；会合服务器地址的保存位置（N6b）。

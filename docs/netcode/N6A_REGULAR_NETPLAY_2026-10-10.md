# Rollback 联机 N6a：常规局域网联机（2026-10-10，核心 r45）

依据：`docs/netcode/ROLLBACK_NETCODE_TASK_2026-10-09.md` 第 7 节 R4、R6、R7、R8；开工说明 `docs/netcode/N6_KICKOFF_2026-10-10.md`；
N4、N5、N5.5 文档（网络层、分歧处理、回放与会话驱动接口）。本阶段在游戏窗口中提供局域网与按 IP 直连的常规联机对战；
远程（会合服务器）与观战入口属于 N6b，历史记录与回放界面属于 N6c，自定义联机对战属于 N6d。

## 1. 用户决定

- R7（开工前）：常规联机与原版 Wi-Fi 对战相同，使用存档当前编队与发展等级；输入延迟 2 帧；结束后回到房间；Wi-Fi 式名称输入；
  编队为当前默认编队；暂不计 RP；名称存于当前存档；P2 操作栏位与 P1 相同（原生界面即如此）。
- R8（本对话，2026-10-10）：
  1. 玩家名称原版取自 Google Play，本移植版另设名称输入窗口。
  2. 大厅复用原版 Wi-Fi VERSUS 菜单（头像、留言与 DECK 保持原生）：“朋友對戰 / 排名配對”改为“建立房間 / 加入房間”；
     RANKING 留给 N6c、暂时隐藏；ACHIEVEMENT、Google Play 图标与 VERSUS REQUEST 隐藏；标题保持 “Wi-Fi VERSUS”。
  3. 名片战绩显示本地联机战绩（与名称同存于当前存档目录），不写入原生 Wi-Fi 字段；分數 / 排名显示 “-”。
  4. 支持点击单位发动单体绝招：输入扩展为 32 位，联机协议版本 4。

## 2. 玩家可见流程

1. 主菜单“對戰” → VERSUS 页“局域网”卡片 → 原生闸门合拢后进入 Wi-Fi VERSUS 菜单（场景 66/67）。“远程”卡片仍为“準備中”（N6b）。
2. 首次进入时原版的 Google Play 说明弹窗改为局域网对战说明；未设定名称时弹出名称输入窗口（最多 16 字、48 个 UTF-8 字节；文字经窗口的字符输入回调接收）。
   名称点击名牌可再次修改。
3. 名片：名称、头像、留言保持原生；“戰績（1對1）”为本地联机胜负；“分數 / 排名”为 “- / -”。DECK 按钮进入原生编队页（修改的即为联机所用的当前编队）。
4. 建立房間：房主开放房间，窗口显示房间码（6 位，N6b 观战使用）、本机各网卡地址与端口（默认 47631）、防火墙说明。
   加入房間：列出局域网房间（名称、地址、房间码、状态；版本或内容不同的房间标注且不可加入），另有“輸入 IP”直连。
5. 连接后比较内容清单，不同时双方显示差异并拒绝。房间窗口显示双方名片（名称、战绩、留言）与本方编队；对方编队显示“开战前一刻公开”。
6. 双方按“準備”后以承诺—揭示交换编队与据点基础状态，进入原生对手画面（WiFiDeck 场景 73/74：对手名片与编队），随后开战。
7. 对战：画面不镜像，P1 在左、P2 在右，各自镜头从本方据点开始；本方使用常规底栏（10 格、滚动、AP 升级、弹头车）与点击单位的单体绝招，
   键盘 1–0、空格、`、- 同样可用。不暂停：Esc 打开“對戰選單”（音乐、音效、投降、返回对战），对战照常进行。右上角显示 Ping。
8. 结束（分出胜负、投降、断线、分歧、对方离开）后经闸门回到房间窗口，显示上一局结果；“再戰”需双方再次确认，“離開房間”回到大厅。
   每轮自动保存回放（N5.5）；分歧时保存分歧报告（`%LOCALAPPDATA%\MSD_WINDOWS_S1XLV\netplay\desync\`，`MSD_DESYNC_DIR` 可改变）。

## 4. 实现

### 4.1 输入（协议 4，回放 schema 2）

每帧每方一个 uint32：位 0–3 出兵格号 + 1，0x10 据点升级，0x20 全体绝招，0x40 弹头车，0x80 投降，位 8–31 单体绝招目标的单位实例号 + 1。
应用顺序与条件同原生：出兵经 `isUnitCreate` 与 vtable +0x94；单体绝招与原生 `onGameScreenTouchEnded` 相同，本方、绝招可用、+0x3d4 为 0 时经 vtable +0x98 发动。
投降位不改变模拟：双方在逻辑帧确认时记录第一个含投降位的已确认帧，对战驱动据此结束本轮（第 4.6 节）。

### 4.2 核心 r45（钩子版本 22）

- 捕获（功能位 1024，`LAB_FLAG_NET_CAPTURE`）：原生底栏的出兵（0x101d738b）、弹头车（0x101d7357）、据点升级（0x101d7405）与点击单位的单体绝招
  （`touch_activate`，0x101d76d3）不再直接执行，改记入核心静态缓冲区（32 项，(种类, 值)），由 `msd_netplay_take_actions` 取走；
  屏幕道具（0x101d74f9）在联机中视为未点中。缓冲区位于客体内存之外，不受回滚影响。原生的可否判定（AP、冷却、人数）在捕获前照常进行。
- drawConv 替换表：条目上限 8 → 16；转换项为 0 时按 y 坐标匹配任意转换项（大厅隐藏 VERSUS REQUEST 下方的选择框）。
- `MSD_Core_LAB_r45_20261010.dll`（27,202,124 字节，`--no-activate --no-sha256` 构建）；钩子关闭时与 r44 行为相同。

### 4.3 编队与发展进度

- 编队：`GetDeckUnitSaveData(格, -1)`，与 World / EVENT 出击（`BattleStartSetUnit`）相同的当前默认编队；未拥有与内部单位的格为空；社区单位写稳定键。
- 等级：存档单位等级（`GetUnitLevelSaveData`）+ 1。
- 据点基础状态：原生 `BattleStartCreateBattleStatus`（我方阵营强化与人质效果）得到 17 个字；按原版 Wi-Fi 对手数据（`MakePlayerInfo` → `BattleStartSetStatusEnemy`）的规则
  规范化：第 3 字为 40，第 8、14–16 字为 0（原版只用于本机的战前道具与人质），第 6、7 字取低字节。双方都按此规则建立，模拟对称。
- 承诺—揭示：承诺覆盖编队与基础状态；揭示后检查结构（`status_error`：长度、规范化规则、生命 / AP 上限、人质倍率 0–100 的有限浮点）。
  只有一方提供基础状态时以 `status_missing` 拒绝。对方单位的实际数值由本机按相同内容计算，并由第 0 帧单位摘要比较（N5）。
- 开战：LAB 按本场设定建立双方编队后，对每方写入同阵营标志（控制器 +0x3a0，按编队单位阵营）并调用 vtable +0xd4 `setupBaseStatus`。

### 4.4 P2 视角（画面不镜像）

P2 一方开战前把原生底栏（`BattlePlayerOperator`）绑定到 P2 控制器：交换 P2 出兵格图集（LAB 为双方建立的同一分配）、+0x18 控制器、
按 P2 出兵格数重算最大滚动（+0x68），并把 `BattleScene` +0x2c / +0x64（原生界面事件的本方队伍与成员）改为 P2；第 0 帧后镜头移到 P2 据点。
控制器须在绑定之前取得（`BattleMain::getPlayerController` 按 +0x2c 选择），并在第 0 帧基准建立期间以此覆盖 LAB 的控制器查询。
这些属于本地界面状态；结束时还原，由 LAB 按原生方式释放图集。

### 4.5 窗口内运行与回滚

- 大厅在原生转入 `SC_BattleStart`（105）时改由 LAB 开战，对战驱动 `RegularDriver` 经会话驱动接口（`probe.session_driver`）逐帧推进：
  等待开战 → 第 0 帧 ready/go（最多 60 秒）→ 对战 → 结束后闸门合拢、回到场景 66。
- 联机期间 LAB 开关（完全控制、双方 AI、自动绝招、支援）一律关闭，结束后还原；LAB 分栏底栏与反馈不启用。
- 触点只在实际显示的帧送入原生。回滚时以下本地界面状态保持当前值：`BattlePlayerOperator` +0x10..+0x78（按压、拖动、滚动）、
  `TouchEvent`（0x1e0 字节）、`BattleScreenTouch` 的 5 个触点记录（BattleMain +4 指向对象的 +4..+0x40）、音乐 / 音效开关（app +0x3d5c）与镜头。
- 校验：BattleMain 读取范围（0x100 字节）中的 `BattleScreenTouch` 触点记录不计入（第 5 节）；单位的绝招光圈显示类型（+0x3d0）不计入（第 5 节第 10 项）；战斗停止后不计 BattleMain 的结果字段
  （+0x10..+0x60：原生 `battleFinish` 按本方视角写入胜负与用时，两台机器不同）。胜负由双方据点生命与结束帧判定。

### 4.6 结束、投降与战绩

- 结束原因：`finished`（结束帧确认后再过 30 帧）、`surrender` / `peer_surrender` / `draw_surrender`（已确认投降帧；同一帧双方投降为平手）、
  `disconnected`（10 秒无数据）、`peer_left`、`desync`（交换分歧数据后保存报告）、`not_started`。战斗已在更早的已确认帧结束时不计投降。
- 战绩：`win` / `loss` / `draw` 计入本地战绩；断线、对方离开、分歧不计。房间窗口中对方的战绩为连接时的名片加上此后各轮的结果（双方判定相同）。
- 不经原生 Wi-Fi 结果场景（77–80），不调用 `AddWiFiScoreSaveData` 等计分写入（第 7 节验证）。

### 4.7 大厅

- 原生 Wi-Fi 菜单的文字批次在 `draw_text` 中改写：按钮文字、战绩数字（取最后两个数字替换，保留“1對1”）、分數 / 排名、Google Play 说明。
- drawConv 替换表隐藏 Google Play 图标、VERSUS REQUEST、1 對 1 / 2 對 2 切换、RANKING、ACHIEVEMENT，对应触点区域停用。
- 玩家名称写入原生 `CGameCenter` 显示名称（+0x380c，64 字节），由原生名牌显示；对手画面的名称、胜场、留言与头像写入 app +0xc081 起的对手数据；
  原生对手数据的编队只能写 10 位 UnitID，社区单位先写替身单位，进入对手画面（场景 74）后以 `SetWiFiDeckUnit` 写入完整 UnitID 显示。
- 留言文字：取原生留言列表（文字批次第 6 项起），对方留言按留言号以本机语言显示。

### 4.8 开工说明第 4 节各核查事项的结论

## 5. 发现与修正

1. P1 / P2 互换（加入方第 0 帧不一致）：LAB 的控制器查询随底栏控制器变化，原生 `getPlayerController` 随 BattleScene +0x2c 变化；改为绑定视角前取得控制器，
   第 0 帧基准建立期间覆盖 LAB 的查询。
2. 战斗结束后的校验分歧：`battleFinish` 按本方视角写入 BattleMain 结果字段；战斗停止后不计该范围。
3. 网络延迟下的分歧（第 990 帧，BattleMain +0x74/+0x78/+0x7c 为 (80, 577, 1)）：BattleMain 读取范围超出对象本身（0x60），
   其中为 BattleMain 构造时分配的 `BattleScreenTouch`（触点 x、y、按下）。回滚把一方的触点记录恢复为点击前的值；
   改为不计入校验并在回滚时保留（另使一次按下与抬起之间的回滚不再丢失点击）。无网络延迟的测试中双方在同一帧点击相同位置，未能发现。
4. 双方同时投降各记一负：投降原为可靠消息，到达时刻不定；改为输入位，按已确认帧判定。
5. LAB 设定的完全控制（AP 9999）等开关带入联机；联机期间关闭并在结束后还原。
6. 经原生对手画面开战时 LAB 的“等待网络”状态未设定，开战停在等待；战斗进行中即视为完成。
7. 加入方的大厅在首次进入的原生说明弹窗（场景 120）期间被关闭；弹窗场景计入大厅允许的场景，说明文字改为局域网对战说明。
8. 对方名片缺少留言文字、战绩不随各轮更新：按留言号以本机留言列表显示，对方战绩加上本次连接各轮的结果。
9. 对战中菜单的标题原为“對戰中（不會暫停）”，用户指出不适合出现在菜单中；改为与本地双人对战菜单相同的“對戰選單”（各语言同）。
10. 常规联机的回放重算在第 30 帧深度校验值不同（语义字段相同；同步后的两份运行目录互验时发现，此前的测试未重算常规联机回放）。
    诊断（`diag_regular_replay.py`：同一进程单机运行一场后重算其回放，逐区域比较）指出差异只在单位 +0x3d0，即绝招光圈的显示类型：
    常规联机中 `Lab.fix_units` 按视角把双方全部单位设为类型 1，回放按 P1 视角只设定对方单位。该字段只影响显示，改为不计入周期校验
    （`netplay_session.UNIT_AURA`）；修正后第 0、30、60、90 帧完全一致。观战（N6b）重算常规联机时同样依赖这一修正。

## 6. 官方 Wi-Fi 对战地图池

1.46.0 `AppMain::SendStageInfo` 以 `RandomMT % 66` 从 0x8fd760 的 int32 表中取地图（1.24–1.38 为 `% 58`，即前 58 项；1.39 增加最后 8 项）。
`netplay_pool.json` 记录这 66 个 StageID 与来源；联机以双方共同决定的比赛种子均匀抽取（`netplay_match.round_values`）。该文件计入内容清单，双方必须相同。

## 7. 验证

全部使用隔离存档（房主 `tools/netplay_check/fixture`，加入方 `verification/n6a_20261010/fixture_b`：两份发展进度不同的存档），网络限定 127.0.0.1，

## 8. 限制与待办

- 两机（真实网卡上的局域网广播、防火墙、跨 CPU）验收待用户进行；两机验收清单新增 C 组（第 9 节）。
- 只支持 IPv4；无中继；连接不加密（令牌防路径外伪造）。修改过的客户端可谎报发展进度（结构检查只拒绝格式错误与明显越界的值）。
- 对战中的鼠标点击经原生判定后成为输入，生效时刻比本地点击晚输入延迟（2 帧）；网络较差时对方的操作在回滚后才出现。
- 2 对 2、排名配對、VERSUS REQUEST、成就不提供。RANKING 按钮留给 N6c 的历史记录。
- 原版 Wi-Fi 编队（存档中的旧 Wi-Fi 编队数据）不使用。

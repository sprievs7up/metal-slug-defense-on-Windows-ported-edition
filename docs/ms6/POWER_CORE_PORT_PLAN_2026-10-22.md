# 能量核心（Power Core）移植方案：以 MSD 原生沙包 `Donou` 为原生动作类

日期：2026-10-22（Asia/Shanghai）。状态：用户确认（受击槽 7 用方案 A），已按本方案实施于工作区（核心 r78，`docs/POWER_CORE_2026-10-22.md`，AGENTS 第 208 节）；数值待用户给出，两个固定运行目录未同步；未计算 SHA-256。
来源：MSA 7.13.0 的 1575（修筑者）/ 1576（建筑 `EnergyCore1800`），核查见 `docs/ms6/MS6_M45_MSA_UNITS_CHECK_2026-10-22.md`。用户决定（2026-10-22）：能量核心以 MSD 原生沙包 `BattleAction_Donou` 为原生动作类，按槽号重排脚本，用钩子补受击与损毁爆炸；先比较 MSD 工兵交给修筑对象的初始状态，再出方案确认。

## 1. 修筑流程：MSD 与 MSA 工兵的比较

反汇编：MSD `BattleAction_Kouhei::update`（0x101acc50）、`BattleObject::createChildObject`（0x101de224）；MSA `BattleAction_Kouhei::update`（0xf1d490，`KouheiHp` 沿用；MSA 辅助函数无符号，表中 MSA 一列按调用形态推定）。

| 项目 | MSD 1.46 | MSA 7.13.0 |
| --- | --- | --- |
| 修筑对象与修筑时间 | 数据行状态词 40 / 38（沙包工兵 5 → 沙包 4，修筑时间 Lv1 15、Lv40 9） | 主数据表 `m_unit_make`（1575 → 1576，修筑时间 30，各等级相同） |
| 生成位置 | 状态 50 第 1 帧播放槽 10，`createChildObject(修筑对象, …, x 偏移 60, y 偏移 0)` | 同样的 x 偏移 60、y 偏移 0 |
| **修筑开始时交给修筑对象的状态** | **预约状态 141**，并设隐形（`changeStateInvisible(1)`）与禁止绝招（`changeStateDontSpAttack(1)`） | **状态 131**，并设隐形等标志 |
| 修筑期间 | 修筑对象按计时闪色（`childSetColor`），计时达到状态词 38 结束 | 同类处理（未逐条核对） |
| 修筑完成 | 修筑对象预约状态 10、取消隐形与禁止绝招；工兵转状态 141（隐形）→ 142（走回据点后移除） | 修筑对象改为保存的状态并取消隐形（推定） |
| 修筑对象如何处理该状态 | `Donou`：141 → 槽 6（待机） | `EnergyCore1800`：131 → 重算生命、播放槽 7（能量释放）、转状态 75（播完回状态 10） |

结论：以 `Donou` 为原生动作类时，修筑期间核心以槽 6（待机）显示并闪色，完成后进入状态 10。MSA 在修筑开始时会先播放一次槽 7（能量释放），按本方案不重现（如需要，另加一个钩子，见第 7 节第 2 项）。

## 2. MSD `Donou` 的状态与槽（反汇编 0x1016d2d2、0x10173ecc）

| 状态 | 槽 | 处理 |
| --- | --- | --- |
| 10、20、141 | 6 | 待机，不移动 |
| 60 | 7 | 第 1 帧播放槽 7，动画结束后转状态 10 |
| 100、110、120 | 8 | 第 1 帧播放槽 8，动画结束后 `BattleObject::kill`（0x1016d324 的尾调用） |

- **受击**：`Donou::damageAction` 在生命大于 0 时调用 `playHitEffect`（受击闪光）并预约状态 60；生命耗尽时预约状态 100。沙包的击退门槛同为 −100，但 `damageAction` 不经过击退计量，因此不会被击退。MSA 中 1575、5（沙包工兵）与 4（沙包）共用同一动作记录（0x49fa020，`donou.obm`），槽 6 待机、槽 7 受击（3 帧）、槽 8 损毁（16 帧，音效 289 DONO_BREAK），与上表一致。
- 更正：前一份核查文档第 7 节把沙包的状态 60 / 槽 7 写成修筑，实为受击；已在该文档中更正。

## 3. 能量核心（MSA 1576）的脚本

预览：`verification/ms6_m45_msa_units_20261022/preview/1576_slots6_9_zoom.png`（槽 6–9，每 4 tick 一帧）。

| MSA 槽 | 内容 | MSA 中的使用 |
| --- | --- | --- |
| 0 / 1 / 2 | 菜单：待机、行走（同待机）、攻击（槽 7 的静态版） | 菜单 |
| 6 | 待机：核心搏动（子层脚本 11，8 帧循环），受击框 1 | 状态 10 / 20 |
| 7 | 能量释放：五道光束向上半圈放射，攻击框 1（126×89），音效 2516，约 32 tick 后结束 | 状态 75（修筑开始时的 131 与技能反击） |
| 8 | 以 op36 挂上与槽 7 相同的光束子层（无攻击框、无音效），自身 2 帧，32 tick 循环（op5）（2026-10-22 更正：`msa_unit.py` 预览此前不执行 op36，初稿写为“核心发亮”） | 状态 80（MSA 普通受击不进入此状态，推定由硬直类技能触发，未核对） |
| 9 | 损毁：1 帧 3 tick，之后由代码在原点放共用爆炸 0xff04 并移除 | 状态 100 / 110 / 120 |
| 11–34 | 子层与粒子（核心、光束、碎光，op18 渐隐） | 由上述槽引用 |

MSA 专有指令：24 / 26 / 28 / 32 / 57 为空操作，删除；36 改为 op11；35（EveryTimeAtk）只在槽 7。无 op19 缩放，不涉及“不缩小一号”的处理。

## 4. 槽号重排（MSD 描述符）

| MSD 槽 | `Donou` 用途 | 放入的内容 |
| --- | --- | --- |
| 0 / 1 / 2 | 菜单 | MSA 0 / 1 / 2 |
| 6 | 待机、修筑期间 | MSA 6 |
| 7 | 受击（状态 60，播完回待机） | 待定，见第 5 节，建议 MSA 8 的一个周期 |
| 8 | 损毁（播完移除） | MSA 9 |
| 9 | 不使用 | 留空 |
| 11–34 | 子层 | 编号不变 |

脚本编号沿用 MSA（同钢铁哨兵的做法），只替换槽 7、8、9 三项；核查过 7、8、9 不被其他脚本当作子层引用（子层引用只有 11–28 与 33）。MSA 槽 7（能量释放）在方案 A / C 下不被调用；子层 18–21、25–28 含 op2 旋转，MSD 指令相同。

## 5. 受击

`Donou` 原生已有受击状态（闪光 + 状态 60 + 槽 7，不击退），因此受击不需要钩子，只需决定槽 7 放什么：

| 方案 | 槽 7 内容 | 效果 |
| --- | --- | --- |
| A（建议，用户 2026-10-22 选定） | MSA 槽 8 的一个周期（op5 改为 op21，32 tick） | 受击时放出光束约 1 秒后回待机（实施时发现槽 8 带光束子层；另备只保留槽 8 自身帧的开关 `HIT_BEAMS`，见单位文档第 3 节；用户 2026-10-22 确认保留光束） |
| B | MSA 槽 7 能量释放（含攻击框与音效 2516） | 每次受击都放一次光束反击。MSA 中只在技能回避时反击；MSD 中攻击框取哪一组伤害、是否每次受击都重新判定，需另行实测 |
| C | 槽 6 的有限长度副本 | 只有受击闪光，与 MSA 普通受击（默认受击函数只播受击效果）一致 |

持续受击时状态 60 会被反复预约，动画是否每次从头播放待实测。

## 6. 损毁爆炸（核心钩子）

- MSA：槽 9（3 tick）结束后在原点放共用爆炸 0xff04（`0x10e1ea8(对象, 0, 0, 0, 0xff04, -1)`），再移除。
- MSD：`Donou` 状态 100–120 在槽 8 播完时尾调用 `BattleObject::kill`（0x1016d324）。
- 钩子（核心 r78）：在 0x1016d324 处，对带新行为的单位先调用 `BattleCommonActions::addEffect(动作, 对象, 0, 0, 1, 0xff04, −1)`（0x181cd4，MSD 原生 IRON SLIDER 放共用爆炸用同一函数与参数形式），再继续 `kill`。原版沙包 4 与其他 `Donou` 单位不受影响。
- 该调用是钩子内的嵌套调用，建立效果对象时可能扩容对象池，依赖 r77 的堆导入回调（第 203 节）。第 4 个参数 MSD 原生为 1、MSA 为 0，含义实施时核对；爆炸是否自带音效实测后决定是否补音效。
- 行为：新增 `structure_death_effect`（暂名，版本 1，`base_classes` [4]，无参数，效果固定为 0xff04、偏移 (0, 0)）。行为库版本 12 → 13，重新生成 `src/behavior_manifest.inc` 与 `docs/modding/BEHAVIOR_CATALOG.md`；加载器在社区记录中写标志，并检查核心导出的版本函数。

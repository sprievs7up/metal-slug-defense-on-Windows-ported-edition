## 2. 标识与 ID 分配

### 2.1 ID 区段（建议，待确认）

- 原版：0–399，不变。
- 本体内容：1024–2047（1024 个）。现有 20 条保持 1024–1043 不变，后续本体单位继续向后追加。
- 模组：2048–5119（3072 个），由加载器按“稳定键 → ID”映射分配。映射持久化在用户目录的 `mods_ids.json`，同一模组跨启动保持相同 ID；停用后保留映射，重新启用时恢复原 ID。
- 原生记录表覆盖 1024 到当前最大 ID，空位为“未启用”记录。
- 分区的理由：本体以后追加单位时，不会占用或挤动模组的 ID，玩家存档里的编队不会错位。

### 2.2 稳定键

- 本体：`s1xlv.<名称>`（现有规则）。
- 模组：`<模组 id>.<名称>`，模组 id 为小写字母、数字与下划线。
- 关卡、EVENT、覆盖补丁引用单位时，一律使用稳定键或原版 UnitID（0–399），不使用 1024 以上的数字 ID。

## 3. 内容格式草案

### 3.1 单位文件（从 `registry.json` 拆分）

- 本体：`community_content/units/<key>.json`；模组：`mods/<模组 id>/units/<名称>.json`。
- 字段沿用 schema 2 现有的 48 个字段，不写 `id` 与 `icon.index`，改由加载器分配。迁移时现有 20 条逐字段搬出，加载结果（数据行、描述符、ID）必须与迁移前逐字节一致。
- 字段分为三类：
  - **基础与经济**（16 个必填）：`key`、`base_id`、`faction`、`identity`、`shop_price`、`available_from_start`、`ap`、`hp_multiplier`、`knockback_threshold_multiplier`、`special_damage_multiplier`、`production_reference_id`、`production_interval_multiplier`、`icon`、`animations`、`localization`、`textures` 或 `texture`。
  - **数值倍率**（可选，模组可直接使用）：`move_speed_multiplier`、`attack_range_multiplier`、`damage_multiplier`、`knockback_distance_multiplier`、`ballistic_range_multiplier`、`attack_wait_multiplier`、`normal/special_projectile_distance_multiplier`、`special_cooldown_multiplier`、`attack_range_categories`、`attack_attributes`、`shop_unlock_reference_id`、`world_clear_reward`。生命值与击退门槛的联动沿用 AGENTS 第 6.1 节，校验器给出提示。
  - **特殊行为**（迁入 3.3 节的 `behaviors`）：`child_unit_key`/`landing_unit_key`/`internal_only`、`shot_action_reference_id`、`recovery_animation`、`preview_unit_key`、`construction_time_multiplier`/`summoned_unit_key`/`summon_interval_*`、`ground_special_attack`、`flame_interrupt`、`attack_parameter_references`、`normal_attack_range_from_projectile`、`sprite_descriptor`、`menu_reference_id`。
- `status_word_values`（直接写入数据行的绝对值）属于底层字段，建议只开放给本体使用，模组不可用（待确认）。

### 3.2 `mod.json`

```json
{
  "schema": 1,
  "id": "author_mod",
  "version": "1.0.0",
  "name": {"EN": "...", "ZS": "..."},
  "author": "...",
  "license": "CC-BY-4.0",
  "game_version": ">=1.48",
  "behavior_library": ">=1",
  "depends": [{"id": "other_mod", "version": ">=1.0"}],
  "conflicts": [],
  "content": {"units": "units/", "campaign": "campaign/", "events": "events/", "patches": "patches/"}
}
```

加载顺序由 MOD 页决定，不写在 `mod.json` 中。资源放在 `assets/`，按文件名引用，加载器校验图集尺寸、调色板和矩形边界。

单位文件中：

```json
  {"name": "summon_on_build", "version": 1,
   "params": {"summoned_unit": "author_mod.box", "construction_time_multiplier": [1, 1], "summon_interval_multiplier": [5, 4]}}

```

行为库清单（C++ 侧登记，供校验与作者工具读取）：

```json
{"name": "summon_on_build", "version": 1, "base_classes": [77],
 "params": {"summoned_unit": {"type": "unit_key", "required": true},
            "construction_time_multiplier": {"type": "rational", "min": [1, 10], "max": [10, 1], "default": [1, 1]}},
 "slots": [10], "states": [30, 40], "doc": "..."}
```

现有单位对应的首批行为：`para_drop_transform`（伞兵）、`summon_on_build`（MKII）、`insect_swarm_release` 与 `recovery_slot`（木乃伊）、`flame_burst_interruptible`、`single_knockback_per_special` 与 `ground_special_attack`（KT-21）、`retained_special_weapon`（十类角色，原版单位适配，不面向模组）。具体在 M2 阶段定义。

### 3.4 停用模组时的存档处理（建议）

- 进度（等级、拥有状态）按稳定键保留在 `community_progress.json`，不删除。
- 编队中引用了已停用单位的格子：加载后在内存中视为空格，并另行记录原值，正常保存时不写回原生存档；重新启用后恢复。实现细节在 M4 阶段。
- 关卡或 EVENT 引用了未安装的单位时，整个模组校验失败并被跳过。

### 3.5 覆盖补丁（修改原版或本体数值）

`patches/*.json`，每项形如 `{"target": "unit:3" | "unit:s1xlv.kt21", "field": "hp_multiplier", "value": [3, 2]}`。只允许修改 3.1 节“数值倍率”类与经济类字段；同一字段被多个模组修改时，后加载者生效。

## 6. 用户确认结果（2026-10-09）

1. **ID 区段**：本体 1024–2047（现有 20 个保持 1024–1043），模组 2048–5119，按 2.1 节实施。
2. **底层字段**：`status_word_values` 等直接写入数据行的字段**开放给模组**。M1/M3 需要相应加强：
   - 校验器检查状态词编号和等级锚点范围；
   - 这类字段计入联机内容清单；
   - 作者指南中标明风险。
   3.1 节“建议只开放给本体”的表述以本条为准。
3. **覆盖补丁范围**：只允许修改数值倍率和经济字段（3.5 节），不允许改动画、贴图与行为。
4. **摘要算法**：模组资源校验与联机内容清单改用 BLAKE2（Python `hashlib.blake2b`），并按“文件大小+修改时间”缓存结果。现有本体注册表 `assets` 中的 SHA-256 记录在 M1 拆分时一并迁移。该摘要属于游戏功能，不受 AGENTS 第 12.1 节（代理验证停用 SHA-256）约束。

第 4 节已无待确认事项，可以进入 M1。

## 7. 单位目录接口（为单位浏览/选购界面重设计预留）

用户要求（2026-10-09）：单位数量达到上千时，现有浏览方式会很难用，需要留下接口，供以后重新设计整个单位浏览与选购界面。新界面需要包括：购买反馈；近战、远程、特殊攻击分别展示；HP、AP、攻击力、抗击退等核心数据的详细信息；能够快速找到单位。本节只定义接口与数据要求，界面本身作为新阶段 U1（见模组任务书第 5 节）。

### 7.1 原则

- 新增宿主模块 `unit_catalog.py`，作为“单位数据与操作”的唯一入口，与界面无关。商店、强化列表、编队选择、LAB 选单位，以及以后的新界面都从这里取数据。
- 目录只读取数据。购买、强化、编队等操作仍走原生既有的事务路径（原生商店购买、MSP 强化、编队存档写入），目录只负责调用并返回结果，不直接写存档，以保证存档一致性。
- 界面可以替换：原版界面、宿主自绘界面（类似 LAB 准备界面）或以后的新设计，都调用同一套接口。

### 7.2 单位条目（`UnitEntry`）

| 分组 | 字段 | 来源 |
| --- | --- | --- |
| 身份 | 稳定键、UnitID、来源（原版 / 本体 / 模组 id）、阵营、身份文本 | 原版数据行；单位文件 |
| 文本 | 当前语言的名称与描述（11 种语言） | `GetMenuUnitName` 等原生接口；单位文件 `localization` |
| 标签 | 兵种类别（步兵、载具、飞行、建筑类、召唤类等）、系列、自定义标签 | 由原版动作类与行为自动推导，单位文件可选 `tags` 补充 |
| 经济 | AP、勋章价格、解锁条件（文本与当前是否满足）、是否已拥有、等级、等级上限、再出击冷却 | 原生商店与等级接口；单位记录 |
| 核心数据（按等级） | HP、击退门槛（抗击退）、移动速度、AP 返还 | `BattleInfo::getUnitStatus`（状态 +0xc HP、+0x10 击退门槛×100 等，LAB AI 已在用） |
| 攻击模式 | 近战、普通（远程）、特殊三组，每组含伤害、击退力（第二参数）、属性、射程分类、等待或冷却；该组是否存在 | 同上（状态中三组参数），射程分类为数据行词 48/49 |
| 衍生指标 | 每秒伤害估算、综合强度（可与 LAB AI 的单位价值公式共用） | 由上面的数据计算 |
| 展示资源 | 图标（页与矩形）、动作预览入口（原生 Action Viewer，场景 119） | 图标表；单位文件 |
| 行为 | 所用行为名与参数（供详情页说明特殊能力） | 单位文件 `behaviors` |

### 7.3 查询接口

- `list(filters, sort, page, page_size)` → 条目列表与总数。
  - 筛选条件：阵营、来源（原版 / 本体 / 某模组）、已拥有 / 可购买 / 未解锁、兵种标签、具备某种攻击模式、AP 或价格区间、文本搜索（当前语言名称与稳定键）。
  - 排序：AP、价格、HP、每秒伤害、综合强度、抗击退、名称、新加入。
  - 排序结果稳定：同值时按 UnitID 排序。
- `detail(key, level)` → 单个单位在指定等级下的完整条目，可用于等级对比。
- `compare(keys, level)` → 多个单位的数据对比。

### 7.4 操作接口与反馈

- `purchase(key)`、`upgrade(key)`、`set_deck_slot(group, slot, key)` 返回统一的结果对象：成功或失败、原因代码（勋章不足、MSP 不足、未解锁、已拥有、等级已满、组合包冲突等）、货币变化，以及操作后的条目。
- 结果对象就是“购买反馈”的数据来源。新界面可以据此播放原生音效、显示获得动画或提示，原生界面也可以继续沿用自己的反馈。

### 7.5 性能要求

- 条目索引在主菜单空闲时分帧建立（同 P1 准备界面预热的做法），按语言缓存。
- 等级数据按需计算并缓存，4096 个单位不需要一次性计算全部 40 个等级。
- 图标按页按需加载。

### 7.6 对 M1 的要求

- 单位文件加入可选字段 `tags`（字符串列表）。来源字段由加载器填写（本体或模组 id）。
- M1 实现 `unit_catalog.py` 的数据读取部分（7.2、7.3 节），并用 LAB 选单位界面作为第一个使用者验证（500 到 4096 个测试单位下的筛选、排序与翻页耗时）。
- 7.4 节的操作接口与新界面在 U1 阶段实现。

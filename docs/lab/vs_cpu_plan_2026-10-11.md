# VS CPU（与 CPU 对战）规划（2026-10-11）

状态：C1–C3 已实施（第 11 节，核心 r46），等待用户实机测试。第 1–10 节为规划与审计记录。

## 1. 用户要求

1. VERSUS 页在 LOCAL 左侧新增第四个入口 VS CPU，四张卡整齐排列。现有卡片的间距与尺寸保持，四张卡整体横向平移。
2. 进入后的准备界面与本地双人对战基本相同：双方单位、等级、据点等级、优势设定与地图均可设定（与 LAB 相同）。
   玩家选择所在一边（P1 或 P2），CPU 自动分配到另一边。CPU 强度采用 LAB 的 AI 段位，玩家选择要挑战的段位。
3. 战斗中玩家的操作界面采用原版游戏的界面（单方 10 格底栏），LAB 与本地双人对战的分栏底栏不使用。
4. 玩家点击绝招已就绪的本方单位即可释放绝招。本方光圈颜色随所选一边：P1 为蓝色，P2 为红色。
5. CPU 方单位的绝招光圈与绝招等待条隐藏，玩家无法从画面判断 CPU 单位的绝招状态。
6. 胜负后的流程与 LAB 相同：MISSION COMPLETE / MISSION FAILED 演出播放完毕后关闸，开闸回到准备界面。
7. 入口插画由用户绘制，项目预留位置并给出像素尺寸。

## 5. 战斗

现有常规联机（N6a，`netplay_mode == 'regular'`）已实现“原生单方底栏 + P2 视角”，VS CPU 复用该路径，不使用联机捕获与网络。

- 界面开关（`lab.header_flags`）：VS CPU 采用 `AUTO_SPLIT | SUPPORT | AI_TIER | SE_EXTEND`，不设 `ENEMY_GAUGE`（CPU 等待条隐藏）、
  `ENEMY_TOUCH`（不能点击 CPU 单位）、`SPLIT_BAR`（原生 10 格底栏）、`VERSUS`（胜负演出按玩家视角）、`VS_CURSOR`、`NET_CAPTURE`。
- 玩家选 P2：沿用 `netplay_regular` 的 `bind_view` / `swap_gfx` / `unbind_view`，开战时镜头移到 P2 据点，画面不镜像。
  原版快捷键（数字键出兵、Space、反引号、`-`、`=`）在调用时解析当前可见底栏所属控制器（第 5 节），P2 视角下作用于 P2。
- 点击释放绝招：原生对本地队伍单位的点击处理；P2 视角下由视角绑定决定本地队伍。
- 光圈：玩家单位 P1 为原生蓝色渲染器，P2 为 LAB 红色渲染器（`ensure_red_renderer`）；CPU 单位不设渲染器。
  原生 `createUnit` 按对象管理器的本地队伍为单位设置渲染器，玩家为 P2 时 CPU（P1）单位会获得原生渲染器，需逐帧清除，
  清除方式（`setEffectRenderer` 的参数或直接写 +972/+976）在开工时核查。
- CPU：`apply_ai` 对 CPU 一侧启用所选段位，玩家一侧 AI 关闭。
- 敌方 AP 框、敌方 LV UP / ATTACK 横幅、敌方金币等 LAB 双侧反馈（第 57 节）在 VS CPU 中不显示，需确认常规模式下的开关是否已覆盖。
- 存档：沿用 LAB 存档隔离（内存存档映像快照与还原），不发放奖励，不写入原生 Wi-Fi 计分。

### 10.2 原型（四张卡）的规则与结果

1. 三张原生卡片任务在页面打开（`open`、大厅返回的 `follow_lobby_return`）的同一调用中写入新坐标，每帧原生步进前核对；

3. 第四张卡的函数每帧对齐 LOCAL 卡；透明度在绘制时由核心钩子取 LOCAL 卡的当前值（钩子第 23 版，`GT_MenuGenrePanelDraw` 入口，
